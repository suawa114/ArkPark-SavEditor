## 通缉值的定位与修改边界

资源 `/Game/ArkPark/Modes/PCs/故事模式/PC_方舟乐园`：

- `ChildProperties` 中 `通缉星进度` 类型是 `Vector2D`，该字段位于运行中的 PlayerController，不在 `SG_ArkPark2_C`。
- `增加通缉星进度` 函数（export 175）参数 `ADD` 为 Double，转入主事件图语句 242281。
- 主事件图先检查 `剧情任务索引 > 45`（242382–242438），之后显示 `+{nxx}通缉值`（242691），把 `X + ADD` 截断至 `[0, 99999999]`（242834–242972），写回 `通缉星进度` 并保留 Y（243018）。
- 后续 X 与 500 比较，并依据警卫与追逐警车是否存在执行分支（243045–243539）。这说明它不只是 UI 数字，还参与运行时追捕逻辑；不能据这个阈值把整个系统误称为 500 上限。
- 图中另有把该向量写成 `(0, 999999999)` 的语句 243723。它的完整调用前置未核实，不能仅据相邻排布把它归入“清空通缉星”函数。
- `UII通缉星进度`（export 37）接收整数数量，通过控制台 UI 添加对应星数。星数与进度 X 不是同一个字段；本轮未完整还原星数换算。

真实存档完整解析结果及已知资源字段提供了交叉核对：主存档、家园、全局设置及两份搬迁状态均没有发现名为通缉值、通缉星或 wanted 的字段；主存档保存图 213560–215686 枚举货币、剧情、地区信息、日期、统计等，没有把 `通缉星进度` 传入 SG；加载图 217158 的 `下载玩家数据` 参数同样没有通缉字段。

因此不应在 `.sav` 中添加自造的同名属性来宣称已经修改通缉值。运行时读取/修改或游戏资源模组是另一个技术范围，本轮未实现，也未修改进程。剧情期间 UI 也可能由任务脚本临时显示固定数量的通缉星，改剧情索引不等于单独控制追捕。

## 剧情进度的保存、载入与风险

`SG_ArkPark2_C.剧情任务索引` 是 `IntProperty`，4 字节，存储范围 `-2147483648–2147483647`。这是格式可表示范围，不能当成游戏合法阶段范围。

当前第一槽为 49，第二槽为 54。PC 保存图 214478 把运行时索引写到 `SG_Base.剧情任务索引`；加载图 217158 读取 SG 的同名属性作为 `下载玩家数据` 的“剧情任务ID”，100791 再赋给运行时索引。`剧情任务结束`（export 171，入口 187581）先通知 HUD，然后执行 `索引 + 1`（187663–187732）。

已做内存副本验证：

| 文件 | 副本修改 | 实际变化 | 玩家原文件 |
|---|---|---|---|
| `AT_ArkPark0.sav` | 49 → 50 | 长度不变，仅目标整数内的 1 字节变化，重新解析为 50 | 未变化 |
| `AT_ArkPark1.sav` | 54 → 55 | 长度不变，仅目标整数内的 1 字节变化，重新解析为 55 | 未变化 |

偏移只记录为本次样本证据，不可作为不同存档或版本的硬编码偏移。

现有任务文本目录包含 0–69 的分支记录，已观察到任务调度器按 1–67 分支启动不同逻辑；68、69 的目录文本为空。空文本不能据此认定通关、废弃或安全终点，不能把文本目录的 70 项当成可随意选择的 70 个安全进度。

以下直接脚本证据说明不能只用一个索引保证剧情一致：

- `BP_剧情管理器` 对不同索引采用不同检测条件：人物/任务点距离、背包物品、弹药、服务器时间、警卫数量、家园舒适度、等级等；例如第 54 阶段在 14605–14728 检查舒适度达到 2500，再触发 `任务54结束`，第 56 阶段在 14908–15048 检查家园等级至少 6。
- PC 剧情图按索引装载不同剧情关卡、生成剧情角色与代班玩具、设置任务点，个别分支还直接把索引改成 17、51、57 等（如 179842、182570）。正常流程不是纯粹连续递增。
- 第 55 阶段结束入口 202486 会进入 202430 分支，改变“禁止生成顾客BB”状态、查找店员并继续执行图；第 56 阶段继续入口 201704 则转向专属 NPC 流程。直接在退出状态把索引加一，不会执行退出前旧阶段这些事件。
- 存档另有 `S_地区信息`、`击败BOSS`、`C_解锁的船只`、`档案`、`S_可修缮的建筑物`、员工等独立持久状态；保存图分别写它们。它们与每个阶段的完整依赖、奖励和回退规则尚未逐个还原。

可行方向是以明确任务为单位、逐项验证的“实验性阶段调整”，或通过满足指定任务的持久条件让游戏正常完成任务。不能把任意前跳、回退或写入极大索引包装成可靠解锁/通关；现有高级数值编辑能写入索引也不改变这一限制。当前未确定一个可对全部存档保证安全的阶段修改范围。

## 存档天数与世界岛日期

真实主存档中，第一槽 `世界岛日期=14`、`世界岛星期=7`，第二槽为 `18`、`4`。这些字段属于游戏世界日历。

名称为 `拉面龙开业时长` 的字段在 GVAS 中是 `DateTime` 的 Ticks。PC 图 24638 调用 `KismetMathLibrary.Now()`，24666 写入 `拉面龙正式开日日期`，215343 将这个日期保存进 `SG_Base.拉面龙开业时长`；加载后 100086 仍赋回“正式开日日期”。因此其含义是现实时间点，不能当作游戏累计时长或累计天数。文件修改时间也只表示文件最后写入，不等于创建时间或游玩天数。

本轮没有发现独立“存档天数”字段。槽位摘要可如实显示世界岛第 N 天；如同时保留“存档天数”栏，应显示“未单独记录”，避免把同一指标冒充两项。如果用户所说的存档天数指世界岛天数，可统一说明，两者来自同一字段。
